# AMR Platform v0.1.3 — Readiness Contracts

v0.1.3 adds fail-closed lifecycle provenance and deterministic runtime readiness while preserving the established simulation, mapping, localization, navigation, and browser-dashboard interfaces.

## Highlights

- Authoritative, read-only lifecycle snapshots with transition name, UUID, heartbeat, and a three-second remote-state lease.
- Provenance-aware orchestration with synchronous refresh and two-pass final verification. Missing, expired, inconsistent, or changing evidence cannot authorize success.
- Readiness contracts for simulation, mapping, localization, and navigation retain every blocked dependency, reason, and operator guidance.
- Live ROS observation covers topics, TF, services, action servers, controller state, maps, localization, and Nav2 lifecycle state.
- Exact process identities, descendant refresh, and two-scan convergence prevent false shutdown success.
- Ordered teardown and explicit propagation of startup, stop, rollback, cancellation, timeout, and final-verification failures.
- Navigation goals remain unresolved until Nav2 supplies a terminal result.

## Validation

The released implementation was validated locally on Ubuntu 24.04 with ROS 2
Jazzy and Gazebo Harmonic: source syntax, ROS build, 565 tests across 26 CTest
targets, simulator launch regression, headless dashboard integration,
public-launcher lifecycle integration, and 34/34 runtime acceptance checks. The
runtime gate covered simulation, mapping, localization, navigation, rollback,
recovery, cleanup, registry emptiness, and critical-node uniqueness.

GitHub Actions run `42301211782` passed both native ROS 2 and Docker jobs for
release commit `16d3f0dc28b1cd7ab0f90a095fd531a694b06b7b`.

## Known limitations

- Validation is simulation-only. Physical hardware, safety certification, and hardware-in-the-loop behavior are not claimed.
- Hosted CI does not exercise interactive Gazebo GUI scenarios.
- Five internal `/simulation_readiness_probe` graph entries may be present; the critical-node oracle excludes these noncritical probes.
- Runtime maps remain user data outside the repository by default.
- Final lifecycle verification reports external irreversible effects but cannot reverse them.
