## Accepted v0.1.3 interfaces and invariants

- `/simulation/status` and `/mode/status` remain domain status topics; `/platform/readiness` carries structured readiness; `/platform/lifecycle/transition` owns aggregate transitions.
- Manager lifecycle state uses transient-local state/heartbeat plus the read-only `GetManagedComponentState` service.
- Lifecycle, readiness, operating mode, and transition phase remain separate concepts.
- ACTIVE cannot be accepted from missing, expired, wrong-runtime, inconsistent, or changed provenance. The remote lease is three seconds; aggregate success requires two stable authoritative reads.
- v0.1.4 consumes the existing readiness profiles and preserves every failed dependency; it must not create a parallel readiness API.
- Navigation goals remain unresolved until a terminal result. Mode changes must reject or safely cancel an active goal without fabricating completion.
- Process signalling requires exact persisted ownership; descendants refresh before termination and shutdown converges across two scans.
- Startup, stop, rollback, and final-verification failures remain distinct.
- SLAM owns `map -> odom` while mapping; AMCL owns it during localization/navigation; the current controller owns `odom -> base_link` until a later tested change.
