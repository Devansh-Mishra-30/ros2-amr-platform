# v0.1.3 Media Capture Plan

Capture on Ubuntu 24.04 with ROS 2 Jazzy and Gazebo Harmonic after the exact release commit passes validation.

## Preparation

```bash
cd /home/devansh/robotics_projects/ros2-amr-platform
git switch --detach v0.1.3
./scripts/build.sh
./scripts/test.sh
./scripts/run.sh
```

Confirm rosbridge is connected at `http://localhost:8080`. Use one clean runtime instance and stop the active mode and simulation between setups.

## Shot list

1. **Startup, 15–20 s:** show `./scripts/run.sh`, the connected dashboard, warehouse selection, and simulation reaching running plus `simulation_ready`.
2. **ROS/Gazebo, 15–25 s:** show Gazebo and `ros2 node list` or `ros2 topic list`. Verify `/clock`, `/scan`, `/diff_drive_controller/odom`, `/tf`, and `/joint_states`; do not imply measured performance.
3. **Dashboard, 15–20 s:** show environment, simulation status, modes, readiness, and emergency stop. Verify dashboard and ROS topics agree.
4. **Mode transitions, 20–30 s:** Manual → stopped → Mapping. Verify `ros2 topic echo /mode/status --once`; only one mode may be active.
5. **Mapping, 30–45 s:** with `mapping_ready`, drive a short loop, save a uniquely named map, and show the saved inventory. Verify the YAML/image exist; do not call a short demo a quality benchmark.
6. **Localization, 20–30 s:** select the saved map, start Localization, and provide an initial pose. Verify map, AMCL pose, TF, and readiness agree; do not claim accuracy metrics.
7. **Nav2, 30–45 s:** with valid localization and `navigation_ready`, submit one reachable map-frame goal and show feedback through the terminal result. Verify `/cmd_vel/navigation` expires afterward.
8. **Lifecycle/readiness, 15–25 s:** run `ros2 topic echo /platform/readiness --once` and show profile, runtime identity, lease, aggregate result, and all blocked dependencies.
9. **Controlled rejection, 20–30 s:** with simulation stopped, request Mapping or Navigation once, show the dependency-not-ready response, then restore prerequisites and succeed. Verify no mode-owned process started during rejection. Do not kill processes for a public demo.

Before publishing, confirm the tagged commit, accurate status text, no secrets, no duplicate processes, no unexplained warnings, and no physical-hardware claim.
